How version counts work View more

Counts change when the app next reports, not when an APK is downloaded. Offline and uninstalled apps stay at their last known version. Older apps only report daily history, so their version is inferred from the newest activity date, choosing the highest version if several appear that day. New apps explicitly report their current version, including downgrades. Historical activity above is preserved.

About these counts View more

Activity is based on reports received from participating OpenTune installations. It is not a count of unique people. Reinstalling or clearing app data creates a new installation identity. Offline, older or non-reporting apps may be missing; recent reports can arrive later.

Dates use the selected reporting calendar, IST by default, and both range endpoints are included. The UTC view retains older app history. All-time totals and current version counts combine both without counting an installation twice. Zero means no reports received for that date during the recorded period. Dates before the first activity report are shown as unavailable, not zero. A failed request is also shown as unavailable.

Plays per active installation divides plays by distinct installations in the selected period. Daily active counts cannot be added to calculate unique users over a longer period.

Only aggregate counts are shown here. No song history, accounts, device names, IP addresses or installation identifiers are exposed by this dashboard. Website counters and GitHub download events are separate measures and should not be combined.
