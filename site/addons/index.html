Make an OpenTune addon

An addon puts a music catalogue into OpenTune: a label’s releases, a band’s albums, a library of Creative Commons music, or your own recordings. People add it by URL, and its songs show up in their search under its name.

What an addon is

An addon is a web server you run. It answers three GET requests with JSON:

RequestAnswers with
/manifest.jsonWho you are and whose music this is.
/search?q=…&limit=…Tracks that match the words.
/stream/{id}Where one track’s audio file is.

OpenTune never downloads or runs your code. It sends these requests, reads the JSON, and gives the audio file’s address to its player. Any language and any host works, as long as it can answer HTTPS.

Quickstart

The quickest way to try it is the example server in the OpenTune repository, docs/addons/example_server.py. It shares a folder of files named Artist - Title.flac and uses only Python’s standard library.

python3 example_server.py ~/Music/my-releases --port 8080 \
  --id my-label --name "My Label" \
  --catalogue "Releases by My Label. We own the recordings."

With the phone on the same Wi-Fi, open OpenTune → Settings → Connected services → Addons, enter http://192.168.1.20:8080 (your computer’s address), and tap Add. Then search for one of your songs.

If you’d rather write your own, this is a whole addon in Node.js with Express:

const express = require("express");
const app = express();
const tracks = [
  { id: "paper-boats", title: "Paper Boats", artist: "River Choir", album: "Lanterns",
    duration: 201, artwork: "https://cdn.example.com/lanterns.jpg",
    file: "https://cdn.example.com/audio/paper-boats.flac" },
];

app.get("/manifest.json", (req, res) => res.json({
  opentune: 1,
  id: "river-choir",
  name: "River Choir",
  version: "1.0.0",
  catalogue: "Every River Choir album. The band owns these recordings.",
}));

app.get("/search", (req, res) => {
  const q = String(req.query.q || "").toLowerCase();
  const limit = Math.min(Number(req.query.limit) || 20, 50);
  const found = tracks.filter(t => `${t.artist} ${t.title}`.toLowerCase().includes(q));
  res.json({ tracks: found.slice(0, limit).map(({ file, ...t }) => t) });
});

app.get("/stream/:id", (req, res) => {
  const t = tracks.find(t => t.id === req.params.id);
  if (!t) return res.status(404).json({ error: "not found" });
  res.json({ url: t.file, mimeType: "audio/flac" });
});

app.listen(8080);

Manifest

GET /manifest.json. OpenTune reads it when someone adds your addon, and again when they add it a second time to update it.

{
  "opentune": 1,
  "id": "river-choir",
  "name": "River Choir",
  "version": "1.0.0",
  "description": "Folk recordings from 2009 to now.",
  "homepage": "https://riverchoir.example.com",
  "catalogue": "Every River Choir album. The band owns these recordings."
}
FieldMeaning
opentunerequiredThe protocol version you follow. This page describes 1. An app that doesn’t know your version refuses the addon instead of guessing.
idrequiredUp to 64 letters, numbers, dots, dashes or underscores. Keep it the same forever: songs people liked or put in playlists are saved under it.
namerequiredShown in settings and as the heading over your songs in search. Up to 60 characters.
cataloguerequiredOne plain sentence saying whose music this is and why you may share it. Shown to people under your addon’s name.
versionoptionalYour addon’s own version.
descriptionoptionalA line about what’s in the catalogue.
homepageoptionalAn https:// page about you or the music.

Fields OpenTune doesn’t know are ignored, so you can add your own.

Search

GET /search?q=paper%20boats&limit=20. q is what the person typed. limit is how many tracks OpenTune will show; returning more is allowed but wasted. When someone adds your addon, OpenTune also sends one search for test to check that this route works, so make sure it answers even when nothing matches.

{
  "tracks": [
    {
      "id": "paper-boats",
      "title": "Paper Boats",
      "artist": "River Choir",
      "album": "Lanterns",
      "duration": 201,
      "artwork": "https://cdn.example.com/lanterns.jpg"
    }
  ]
}
FieldMeaning
idrequiredYour id for the track, up to 512 characters. OpenTune sends it back in /stream/{id}. Like the addon id, keep it stable.
titlerequiredThe track’s title. Rows without an id or title are skipped.
artistrecommendedCredited artists, as one string.
albumoptionalAlbum name.
durationoptionalLength in seconds.
artworkoptionalAn absolute https:// image address, square, 500 to 1200 pixels across.

Return {"tracks": []} when nothing matches. An error status or a slow answer only hides your results for that search; YouTube Music results still show.

Stream

GET /stream/paper-boats. OpenTune asks this when the track starts playing, not when it’s found or queued, so a link that expires after a few minutes is fine. The id is URL-encoded in the path.

{
  "url": "https://cdn.example.com/audio/paper-boats.flac",
  "mimeType": "audio/flac",
  "bitrate": 920,
  "sampleRate": 44100,
  "bitDepth": 16
}
FieldMeaning
urlrequiredAn absolute https:// address of one audio file. MP3, AAC or ALAC in M4A, FLAC, Ogg Vorbis, Opus and WAV all play. The file server should answer Range requests so seeking is quick.
mimeTyperecommendedThe file’s type, such as audio/flac. It has to start with audio/.
bitrateoptionalIn kbit/s.
sampleRateoptionalIn Hz.
bitDepthoptionalBits per sample, for lossless files.

Answer 404 when you don’t have the track. OpenTune shows the person that it couldn’t play.

OpenTune refuses a stream answer when the url is a playlist or stream manifest (.m3u8, .m3u, .mpd, or a matching mimeType), when the type isn’t audio, and when the answer has "encrypted": true or a drm field. OpenTune does not decrypt audio. An addon has to serve plain files.

Rules

Only serve music you have the right to share. That means music you made, music you have a licence to distribute this way, or music under a licence that allows it, such as many Creative Commons licences. Say which in catalogue.

  • Don’t relay another streaming service’s catalogue, and don’t use other people’s accounts, keys or sign-ins to fetch audio for your addon.
  • Use HTTPS for the addon and for every url and artwork address. Plain http:// is accepted only for localhost, .local names and home-network addresses (10.x, 172.16–31.x, 192.168.x), for testing.
  • OpenTune doesn’t follow redirects on the three addon routes. Answer at the address people add. Audio file URLs may redirect.
  • Keep each JSON answer under 1 MB and answer within 12 seconds.
  • Don’t ask OpenTune to send custom headers or cookies. Put any access token in the file URL and make it expire.
  • Credit artists accurately and don’t label a lossy file as lossless.

Add and test

  1. Check each route in a browser or with curl: /manifest.json, /search?q=test, and /stream/ plus an id from the search.
  2. In OpenTune, go to Settings → Connected services → Addons. Enter your addon’s root address, or the full address of its manifest.json, and tap Add. OpenTune reads the manifest and runs a test search. If either fails, it shows the reason.
  3. Search for one of your songs. Your results appear below YouTube Music’s, under your addon’s name. Tap one to play it.
  4. In the player, tap the quality pill to open Signal path. The source reads Addon · Your name.

Adding the same address again re-reads the manifest. People can switch your addon off or remove it in the same place.

Checklist

  • Manifest has opentune, a stable id, name and an honest catalogue line.
  • /search returns {"tracks": []} for no matches, with id and title on every row.
  • /stream/{id} returns an HTTPS link to a plain audio file, or 404.
  • The file server supports Range and sends a correct Content-Type.
  • Track ids and the addon id don’t change between versions.
  • Every track is one you’re allowed to share.

Troubleshooting

MessageWhat to check
That doesn’t look like an addon addressUse https://, or http:// with a home-network address. Leave off ? query strings.
The addon answered 301 / 302The route redirected. Use the final address, including https:// and any trailing path.
The manifest doesn’t say which OpenTune addon version it followsAdd "opentune": 1.
The manifest needs a catalogue line…Add catalogue, see Manifest.
The search answer needs a tracks list/search has to return an object with a tracks array, also for q=test.
The stream address must be httpsServe audio over HTTPS, or test on your home network.
Addons must link to an audio file…Return the file itself, not an HLS or DASH playlist.
Songs show but won’t playOpen the url from /stream on the phone’s browser. Check the Content-Type and that the link hasn’t already expired.
